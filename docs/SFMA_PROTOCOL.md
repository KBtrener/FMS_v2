# SFMA protocol

The SFMA catalog is transcribed from `sources/live-protocol-reference/fms-sfma/production-bundle.js` (SHA-256 `3d2e5ebc4b2bcceae04f534fcf249107bac28ff7d3548982f7a8963a929e56fc`). The Top Tier order, English pattern names, descriptions, side modes, classification names, breakout titles, sections, steps, standards, and source notes come from that production bundle. `js/sfma-protocol.js` is the versioned application catalog.

Top Tier uses FN, FP, DN, and DP. Single patterns have one classification; the source marks cervical rotation, both upper-extremity patterns, multi-segmental rotation, and single-leg stance as bilateral. Every Top Tier side is required before completion. A breakout is available only after Top Tier completion and when at least one side of its pattern has a classification other than FN. Breakout observations are optional and use the same four classifications; blank values mean the subtest was not performed.

The production bundle provides breakout sequences, standards, and explanatory notes. Those notes are shown as source guidance and do not trigger additional classifications or diagnoses. Breakout activation follows the source's active/passive relationship: local test sections and L/R tests use independent side states; passive branches are evaluated against the matching side of the last active test. Rendering, pruning, and API validation use the same catalog helper. Answers and measurements in branches that become inactive are removed.

Tests that specify angular standards expose degree measurements per applicable side. The source standard is always displayed, and the entered raw value is retained under `protocol_data.measurements` even when it does not determine a classification. Optional rules are stored in `quickscreen_v2.sfma_measurement_rules` using the stable key `topTierId|sectionId|stepIndex|measurementFieldId|side` (empty side for single-sided fields), an explicit comparison operator and threshold, and an output classification. Only an active matching rule calculates an existing SFMA classification; the standard by itself never creates a rule or infers pain. When a rule applies, the calculated classification is shown as derived and cannot be manually overwritten. Without a rule, the existing manual FN/FP/DN/DP choice remains available. Raw values remain available in results and are compared with the closest previous SFMA assessment in the report.

SFMA never produces a numeric total or overall finding. `total_score` and `max_score` remain null. Protocol data, version, Top Tier classifications, optional breakout classifications, and measurements are stored in `assessments.protocol_data`.
